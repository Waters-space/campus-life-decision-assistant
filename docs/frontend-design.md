# 前端页面设计

## 页面目标

前端不是把用户直接丢进空白聊天框，而是先完成三件事：让用户明白应用能做什么、帮助用户快速形成问题、提供进入智能体和校园官方信息的明确入口。

## 用户端结构

1. **顶部导航**：品牌、运行状态、深浅主题和管理入口。
2. **首屏卡片**：通过扇形轮播呈现产品说明、校园图片和信任信息。
3. **场景入口**：餐饮、快递、自习、二手和多模块联动，降低提问门槛。
4. **开始决策**：通过 `VITE_PRIMARY_AGENT_URL` 打开主智能体。
5. **二手交易**：买家进入教材智能体，卖家使用本地演示表单录入商品。
6. **更多内容**：校园新闻检索、标签筛选和常用网站跳转。

## 视觉与交互原则

- 使用暖色、低饱和背景和大圆角，降低工具感，贴近校园生活场景。
- 深浅主题不只改变颜色，还通过星星、云朵等过渡动效传递昼夜切换。
- 卡片动效用于说明层级和操作结果，不让动画阻碍点击或阅读。
- 移动端优先保证按钮尺寸、横向筛选和文字可读性。
- 使用语义化标签、`aria-label`、焦点样式和 `aria-live` 辅助无障碍访问。

## 内容管理

管理端位于 `/admin`，可编辑首页图片、叠加文字、装饰图案、新闻和校园网站。内容保存在 `server/data/managed-content.json`，该文件属于运行数据，不应提交到公共仓库。

首次部署时通过 `ADMIN_INTERNAL_CODE` 创建管理员账号。当前实现适合作品展示和单机部署；生产环境应增加持久化会话、CSRF、防暴力破解、审计日志与备份。

## 智能体入口解耦

前端不绑定具体 UUID，入口来自 `.env`：

```dotenv
VITE_PRIMARY_AGENT_URL=https://your-agent.example.com/chat
VITE_USED_BOOK_AGENT_URL=https://your-used-book-agent.example.com/chat
```

这样更换智能体、域名或平台时不需要修改组件代码。未配置时按钮会以禁用状态说明缺少配置，避免误跳转。
