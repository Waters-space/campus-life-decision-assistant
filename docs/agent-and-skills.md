# 智能体与 Skill 架构

## 智能体职责

智能体不是知识库的简单复读器，而是整个应用的决策编排层。它需要：

1. 理解用户问题属于哪个校园场景。
2. 只调用必要且最匹配的 Skill。
3. 对时间敏感问题先获取当前时间。
4. 对精确导航问题调用路线规划。
5. 综合多个 Skill 的事实结果，给出顺序、依据和限制。

## 六个 Skill

| Skill | 典型问题 | 数据来源 |
| --- | --- | --- |
| 餐饮查询 | 菜品、价格、食堂、营业时间 | 餐饮知识库 |
| 快递查询 | 快递点、地址、取件与营业时间 | 快递知识库 |
| 空闲教室查询 | 教学楼、教室、开放时段 | 教室知识库 |
| 二手教材查询 | 教材版本、价格、卖家说明 | 二手教材知识库 |
| 获取当前时间 | 现在、今天、来不来得及 | 自建时间服务 |
| 路线规划 | 怎么走、距离、步行多久 | 地图 POI 与步行路线 API |

## 从工作流到 Skill

每个业务工作流先在平台中独立调试并发布，再生成 Skill。Skill 的接口文档包含：

- `authentication.md`：说明 Bearer 鉴权方式；真实 Key 由平台变量注入。
- `workflowrun.md`：描述工作流运行接口、请求体、响应和 Security。
- 工作流 UUID：部署者自己填写，不写入公共仓库。
- `SKILL.md`：描述适用场景、调用条件、输入和结果约束。

典型调用链：

```text
用户问题
  → 智能体读取系统提示词
  → 选择必要 Skill
  → Skill 调用 workflow/run API
  → 工作流检索知识库或调用外部 HTTP API
  → Skill 返回结构化结果
  → 智能体综合并回答
```

## 调用规则要点

- “先做哪个”“现在是否营业”必须先调用时间 Skill，再调用业务 Skill。
- “怎么走”“距离多少”“预计多久”且给出起终点名称时调用路线 Skill。
- 一般地址、营业时间或办事顺序不等于精确路线，不应强制用户提供坐标。
- 路线结果只有起点、终点均精确匹配且路径有效时才能输出。
- 一个问题涉及多个领域时调用全部相关 Skill；不为展示能力而调用无关 Skill。

## 系统提示词设计

系统提示词主要包含四层规则：

1. **路由规则**：问题与 Skill 的对应关系。
2. **时序规则**：时间判断、业务查询、路线查询的调用顺序。
3. **事实规则**：不得编造地点、库存、空位、路线和营业状态。
4. **交互规则**：先给结论、最小追问、说明资料更新时间和未知项。

初版 MaaS JSON 输出提示词保存在 `workflow/system-prompt.md`。实际部署时应以智能体平台中的最新提示词为准，并把提示词版本与知识库版本一起记录。
