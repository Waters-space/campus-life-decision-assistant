# 知识库整理与构建

## 分库原则

餐饮、快递、教室和二手教材分别建库。分库可以减少无关召回，也便于单独更新资料、设置检索词和回归测试。时间与路线依赖外部服务，不作为静态知识库内容。

## 推荐字段

所有记录至少保留：

- `name`：地点、菜品、教室或教材名称。
- `aliases`：常用简称、旧称和可能的错别字。
- `campus`、`building`、`address`：地点层级。
- `valid_from`、`valid_to` 或 `updated_at`：资料有效期。
- `source_name`、`source_url`：来源与核验入口。
- `notes`：限制条件与不确定项。

业务字段按场景补充，例如餐饮的价格与营业时段、教室的容量与开放节次、教材的版本与 ISBN、快递点的服务商与取件说明。

## 数据清洗

1. 统一全角半角、数字、括号和空格。
2. 修正已知名称错误，同时把旧写法放入 `aliases`，避免用户仍按旧称查询时完全无结果。
3. 拆分一格中混写的多项信息，避免模型误把不同实体拼接。
4. 对价格、营业时段、容量等字段使用统一格式。
5. 删除无法追溯来源或明显过期的记录。

## 检索与回答边界

- 命中知识库不代表信息实时有效。
- “标注空闲”不等于现场一定无人，也不代表没有临时占用。
- 二手商品的在售状态、成色和联系方式应以卖家确认结果为准。
- 菜品名不能替代官方过敏原信息。
- 未命中时明确说明缺少哪项资料，不用模型常识补齐校园事实。

## 验收

为每个知识库准备正常命中、别名命中、错别字、过期数据、无结果和跨库问题。每次更新后保留测试日期、知识库版本、检索词、召回片段和最终答案，防止局部修正造成其他问题回退。
