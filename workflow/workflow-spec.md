# 校园生活决策助手 Skill 编排规范

## 目标

把业务能力拆成六个可独立发布、调试和替换的工作流，再转换为 Skill 供智能体按需调用。智能体负责路由和综合，工作流负责可靠地获取与处理事实。

## 能力清单

| 工作流 | 输入 | 主要处理 | 输出 |
| --- | --- | --- | --- |
| 餐饮查询 | 用户问题 | 检索餐饮知识库并整理命中资料 | 菜品、价格、营业说明、来源 |
| 快递查询 | 用户问题 | 检索快递知识库 | 网点、地址、营业说明、来源 |
| 空闲教室查询 | 用户问题 | 检索教室知识库 | 教室、容量、标注时段、限制 |
| 二手教材查询 | 用户问题 | 检索二手教材知识库 | 版本、价格、卖家说明、限制 |
| 获取当前时间 | 可选问题文本 | 调用时间服务并解析 | 日期、星期、时间、时区 |
| 路线规划 | 起点、终点、问题 | POI 精确匹配后调用步行路线 API | 匹配状态、距离、用时、步骤 |

## 统一约定

- 工作流响应必须明确成功、无数据、输入不足和上游失败四类状态。
- 知识库结果保留来源、更新时间和命中名称。
- HTTP 请求设置合理超时；失败时返回可读错误，不把异常堆栈交给用户。
- Token、地图 Key 和工作流 UUID 只存放在平台安全变量或服务端配置中。
- 大模型节点只负责结构化与表达，不修改接口返回的名称、数值和状态。

## 智能体编排顺序

1. 解析用户目标与已提供条件。
2. 如果问题依赖当前时刻，先调用时间 Skill。
3. 调用餐饮、快递、教室或二手等必要业务 Skill。
4. 如果用户明确要求精确路线，再调用路线 Skill。
5. 合并结果，先给结论，再给依据、未知项和下一步。

## 版本管理

每次发布记录：Skill 版本、工作流 UUID、模型、知识库版本、系统提示词版本、测试日期和已知限制。工作流 UUID 不写入公共文档，由部署者在平台中自行填写。
